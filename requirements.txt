# Versions are pinned to the environment the paper's experiments ran in.
#
#   pip install -r requirements.txt
#   python common/check_env.py      # verify before running anything
#
# ── torch is deliberately NOT pinned here ──────────────────────────────────
# Container images (RunPod, Colab, NGC) ship torch together with torchvision and
# torchaudio, all built against the same ABI. Replacing torch alone leaves the
# other two on the old build, and transformers touches both at import time, so
# everything dies before reaching this project's code:
#
#     RuntimeError: operator torchvision::nms does not exist
#     OSError: libtorchaudio.so: undefined symbol: _ZN3c104cuda29c10_cuda_...
#
# transformers guards those imports with is_torchvision_available() /
# is_torchaudio_available(), but those only check whether the package is
# *installed*, not whether it *loads* — a broken install passes the guard and
# then raises. So use whatever torch the image already provides.
#
# If torch is genuinely missing, install the trio in ONE command so the builds
# match (this is what the paper's environment used):
#
#     pip install torch==2.11.0 torchvision==0.26.0 torchaudio==2.11.0 \
#         --index-url https://download.pytorch.org/whl/cu128
#
# If you already broke the pairing, repair or remove the companions:
#
#     pip uninstall -y torchvision torchaudio     # fine unless you run stage 2
#
# Stage 2 (image-level experiments) needs torchvision; stages 1 and 3 do not.
# ───────────────────────────────────────────────────────────────────────────
#
# transformers must stay pinned: warmup_ratio was deprecated and then removed,
# which breaks stage3_mitigation on newer releases. The training script converts
# it to an equivalent warmup_steps if it has to, but pinning reproduces the
# reported runs exactly.
